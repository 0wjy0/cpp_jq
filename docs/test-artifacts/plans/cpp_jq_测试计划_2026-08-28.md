# cpp_jq tojson 测试计划 — 2026-08-28

## 1. 概述

| 字段 | 值 |
|------|-----|
| 项目 | cpp_jq |
| 测试目标 | 新增 `tojson` 内置函数(委托 `tostring`) |
| 关联 issue | #5 支持tojson函数 |
| 测试类型 | 单功能测试(CLI 子集,非 Web 应用) |
| 验证级别 | L2(数值准确性) |
| 被测入口 | `build/cpp_jq` CLI |

**说明**:cpp_jq 是命令行 JSON 处理器,**无 Web UI 入口**。本计划将 web-auto-testing 技能的目标"Web 应用测试"适配为"CLI 二进制 + NDJSON 输入/输出"的等价测试形态。步骤 2 应用侦测替换为"侦测 CLI 子命令与 stdin/stdout 协议",步骤 4 测试执行通过 shell 调用完成。

## 2. 测试范围

### 2.1 In-scope(本计划覆盖)

1. **`tojson` 注册可达性**:从外部 CLI 调用 `tojson` 不报 unknown builtin
2. **6 种 JSON 输入类型覆盖**:
   - number(`42`)
   - boolean(`true` / `false`)
   - `null`
   - string(`"hello"`)
   - array(`[1,2]`)
   - object(`{"k":1}`)
3. **`tojson` 与 `tostring` 在 cpp_jq 当前架构下行为等价性**(spec §2 关键事实)
4. **错误处理**:`tojson` 接受任何 JSON 值,不应抛错
5. **README 文档**:Builtins 行包含 `tojson`

### 2.2 Out-of-scope(明确不覆盖)

- `fromjson` 函数(独立需求)
- 自定义缩进 / 格式化参数
- 修改 `tostring` 行为
- 修改 `printer.cc` 架构

## 4. 覆盖率目标

| 维度 | 目标 | 计划值 |
|------|------|--------|
| 类型覆盖率 | 6 种 JSON 类型全覆盖 | 6/6 = 100% |
| 边界覆盖率 | 空值、负数、unicode、嵌套、NDJSON | 全部覆盖 |
| parity 校验 | tojson vs tostring 等价 | TC-19/TC-20 |

## 5. 执行策略

- **执行方式**: shell 调用 `echo "<input>" | ./build/cpp_jq -f /tmp/filter.jq`
- **结果验证**:diff 实际 stdout 与期望 stdout
- **失败处理**:失败用例追加 issue comment,暂停 PR 合并

## 6. 排除范围说明

- **不验证** 与真实 `jq` 的字节级一致性:spec §2 已澄清 cpp_jq 当前架构(总是 dump)导致与 jq 行为存在系统性差异,本计划聚焦于 cpp_jq 内部的 tojson 实现正确性,不与外部 jq 对照。
- **不验证** CLI 帮助文档输出 `tojson`:README 已在 Builtins 行追加,CLI `--help` 不展示 builtin 列表。
